## 0. 执行摘要与已确认决策

**产品定位：** 面向一次基本敲定的旅行，提供“查看每日行程 → 看清每日实际动线 → 查询活动详情与个人备注 → 管理待办 → 一键获取新版行程”的轻量旅行手册。不做复杂的行程规划编辑器。

| 模块 | 已确认范围 | 数据归属 |
|---|---|---|
| 每日行程 | 只读时间线；每项仅显示名称与时间/时间段，按官方顺序排列；点击查看详情 | 官方发布 |
| 活动详情与备注 | 地址、说明、预约状态、导航、关联任务；每项独立可编辑个人备注 | 详情为官方；备注为本机 |
| 每日地图 | 所有明确定位节点；默认显示真实道路动线；可筛选、关闭路线；Google Maps 导航 | 官方发布 |
| To-do | 官方任务 + 本地临时任务；各设备独立完成；不再需要的官方任务归档 | 任务模板为官方；完成状态与临时任务为本机 |
| 同步 | 官方行程/路线/任务可一键拉取，离线保留最近成功版本；不覆盖个人数据 | GitHub/Netlify → 本机 |

**已取消或暂缓：** App 内拖动跨日、活动编辑、Plan A/B 切换、Wishlist、复杂 Reservation 管理、云端双人共享备注、账号登录、自动路线优化与实时交通。

## 1. 产品目标、用户与成功标准

### 1.1 主要使用场景

1. **出发前：** 在手机上核对每天顺序与地点，查看尚未完成的预约事项。
2. **行程调整后：** 用户与 ChatGPT 确认变更，维护者通过版本管理修改官方行程并发布；用户在 iPhone 上一键同步即可看到新版。
3. **旅行当天：** 打开当天时间线，点开活动详情查询注意事项、个人备注；在当日地图查看步行和打车路线，必要时跳转 Google Maps 实时导航。
4. **网络不佳：** 可继续查看上次同步的文字行程、任务、备注；地图无法加载时有明确的降级体验。

### 1.2 不做什么

Paris Pocket 不负责实时路况、代替 Google Maps 导航、帮用户自动订票、保存第三方账号密码，也不自动将本机修改写回 GitHub。后续视觉设计由独立设计讨论确定，本 PRD 不指定颜色、动画或审美风格。

### 1.3 成功标准

- 8 个旅行日的时间线和酒店/行李转场能无歧义显示。
- 云端版本更新后，手机能同步到正确的官方版本；失败则保持旧版本可用。
- 备注、本地任务和本机完成状态跨官方更新不丢失。
- 每日地图的地点不偏移，真实道路路线不被直线伪装；导航优先 Google Maps。
- 官方 To-do 与本地 To-do 清楚可见，逾期及高优先级任务更容易找到。

## 2. 信息架构与关键用户流程

**主要入口：** 全程概览（只读） / 每日行程 / 每日地图 / To-do。活动详情由时间线或地图共用同一入口，个人备注位于活动详情内。

**流程 A｜查看当天：** 选择日期 → 查看仅含时间、名称的时间线 → 点击活动 → 查看详细说明、位置、预订状态和个人备注 → 可跳 Google Maps。

**流程 B｜查看路线：** 选择日期 → 打开地图（默认所有可定位节点 + 已验证的道路路线）→ 可按类型筛选节点或关闭路线 → 点击节点 → 打开同一活动详情。若地图不可用，改看地点列表和 Google Maps 链接。

**流程 C｜同步新行程：** 打开 App 自动检查版本；也可点“一键同步” → 拉取完整官方数据并校验 → 成功后替换官方只读数据 → 本机数据原样保留 → 展示数据版本与上次成功同步时间。

**流程 D｜管理 To-do：** 打开统一清单 → 查看官方任务和本地任务 → 勾选完成 / 创建、编辑、删除本地任务 → 官方更新后仍保留本机勾选；正式归档的官方任务移至“已归档”。

## 3. 功能规格与业务规则

### 3.1 ITINERARY｜只读每日时间线（P0）

**FR-IT-01** 一天包含若干有稳定 `activityId` 的活动，按照官方 `order` 显示，**不得按时间字段自动改序**。  
**FR-IT-02** 时间线上每项只显示“时间或时间段 + 名称”；日期由当天标题显示。活动可以使用精确时刻、范围、上午/下午/晚上或“时间待定”。  
**FR-IT-03** 酒店退房、寄存/取行李、交通换乘、机场出发均可作为活动，不能因为不是景点而省略。  
**FR-IT-04** 点击活动打开统一详情：名称、日期、完整时间、简述、执行说明、地点/地址、官方预约状态、公开链接、导航、关联任务和本机备注。无地点活动隐藏不适用的导航按钮。  
**FR-IT-05** 对外发布的状态必须区分“已确定安排”“待预约/待核实”“可选”“仅后备”；**目标时间不等于已经预约**。  
**FR-IT-06** 官方行程改时刻、改日期、改名称时沿用原 `activityId`，本机备注保留。旅行时区为 `Europe/Paris`；鹿特丹当日当地时间也是同一时区。

### 3.2 NOTES｜活动独立备注（P0）

**FR-NOTE-01** 每个活动有一份本地文本备注，可随时编辑，自动保存，离线可用。  
**FR-NOTE-02** 备注仅按稳定 `activityId` 关联，不按日期/标题匹配。  
**FR-NOTE-03** 官方行程删除活动时，相关本地备注进入可恢复的孤立记录/归档，不能静默删除。  
**FR-NOTE-04** 可导出、导入用户数据备份；导入前校验格式并显示是否会覆盖现有本机记录。  
**FR-NOTE-05** 不将私人确认号、私人电话号码、订票管理链接等敏感数据写入公开官方行程；确需记下时使用本机备注。由于本机存储不等于加密保险箱，界面应提示妥善保护设备及备份文件。

### 3.3 DAILY MAP｜真实地图和预计算动线（P0）

**FR-MAP-01** 每个旅行日拥有独立地图；默认呈现**所有定位明确的行程节点 + 已核验的真实道路路线**，可一键隐藏路线，只看节点。  
**FR-MAP-02** 地图包含景点、酒店、车站、上下客点、寄存/取行李节点等；节点可按类型筛选。筛选只影响可见内容，不擅自重排、重算官方动线。  
**FR-MAP-03** 地点（Place）、活动（Activity）、一次到访（Stop）、路段（Route Segment）须逻辑上区分。例如周三早晚两次到访 GHPR 必须成为两个 Stop，但共享同一地点位置。  
**FR-MAP-04** 路段明确起终点、顺序与建议交通方式（步行、驾车、铁路、轮船或未确定）。混合交通不使用全局单一交通模式。  
**FR-MAP-05** 道路路径**在发布新行程时预先生成并保存**，而非每次打开地图才调用路由服务。路线文件可采用 GeoJSON 等可校验格式；服务选型须验证地图许可、署名、缓存与存储条款。  
**FR-MAP-06** 只展示可靠的真实道路/步行路径；无法生成某段时不画直线假装道路，仍显示起终点与“路线未核验”，不妨碍其他路段。铁路和水路不得用驾车路径代替。  
**FR-MAP-07** 地图点击节点可打开活动详情；活动详情的“地图定位”可聚焦该节点，时间线与地图使用同一 Activity/Stop 数据。  
**FR-MAP-08** Google Maps 是**外部**导航的默认服务，支持“查看本段路线”（指定起终点）与“从当前位置导航”（仅目的地）；打开方式需具备浏览器回退。不在首版实现实时路况计算。  
**FR-MAP-09** 当某段路线、地图底图或网络不可用时，保留文字地点列表与 Google Maps 链接；不保证离线完整底图。  
**FR-MAP-10** 定位须核实到“景点本身 / 实际入口 / 集合点 / 码头 / 酒店前台”等正确语义，不得将花园中心作为已确认的圣诞市集入口，也不得只用名称自动猜位置。

### 3.4 TO-DO｜官方任务 + 本地临时任务（P0）

**FR-TODO-01** 清单统一展示两类任务：① 官方发布，手机不能直接改写其公共正文；② 本机创建，可新增/编辑/删除。两类任务均可在本机勾选完成。  
**FR-TODO-02** 任务唯一必填为名称；其余字段可选：优先级（高/中/低，默认中）、截止日期、相关链接、备注、关联日期或活动。来源与归档状态由系统管理。  
**FR-TODO-03** 默认展示“未完成”；已完成和已归档另设视图。排序规则为：先显示逾期任务（按截止日期从早到晚）；其余按高→中→低，优先级相同则按截止日期从近到远；无截止日期置于该优先级末尾。  
**FR-TODO-04** `dueDate` 是任务应完成的日期，**不等于关联的景点参观日期**；关联可以为空，也可以指某一天或单个活动。活动详情可反向访问关联任务。  
**FR-TODO-05** 官方任务同一目标的小幅编辑保持稳定 `taskId`，保留本机勾选；若任务目标发生实质改变，须创建新 ID，不能继承旧完成状态。  
**FR-TODO-06** 官方取消的任务应被**明确标记归档**并保留最后内容、归档原因（若有）及本机历史状态；归档不等于完成。不能仅因新版数据缺少某 ID 就默默推断任务已取消。  
**FR-TODO-07** 本地临时任务不因官方同步被覆盖或删除；本机任务删除可直接执行。两台手机对所有本机完成状态和本地任务互不影响。

### 3.5 SYNC｜单向官方数据同步与离线（P0）

**FR-SYNC-01** 官方行程、地点、Stop、Route 和官方 To-do 由 GitHub 版本管理，部署在原 Netlify 站点；无需重新添加 iPhone 主屏幕图标。  
**FR-SYNC-02** 分离 `appVersion`（代码）与 `tripDataVersion`（行程数据）。首屏显示版本与最后成功同步时间；打开时检查更新，并提供显式“一键同步”。  
**FR-SYNC-03** 新数据先下载、验证完整性（必填、ID 唯一性、关联有效性、地图轨迹版本）后，**原子性**替换现有官方快照；不允许同步失败时写入半份数据。  
**FR-SYNC-04** 无网络、服务器错误、文件损坏时继续展示最后成功的官方版本及本机记录，并明确告知当前可能不是最新。  
**FR-SYNC-05** PWA Service Worker 不得无限期锁定旧数据；用户触发同步时应能明确请求最新数据，并避免缓存的旧脚本覆盖新结构。  
**FR-SYNC-06** 初版无登录、无云端个人数据同步。两台 iPhone 共享官方内容、独立存储备注/本地任务/完成状态。  
**FR-SYNC-07** 现有 V1 PWA 的本地数据在改版时必须盘点、迁移、测试；不得无条件初始化覆盖旧数据。提供导出/导入备份。  
**FR-SYNC-08** 同步只读的官方数据不允许被本地个人备注反向覆盖；未来若需要云端个人同步，再单独立项。

## 4. 数据所有权与最小数据模型

| 对象 | 必要字段（概念层面） | 归属及规则 |
|---|---|---|
| Trip / Day | `tripId`, `tripDataVersion`, `date`, `timezone` | 官方；2026-12-07 至 2026-12-14 |
| Activity | `activityId`, `dayId`, `order`, `title`, `timeLabel`, `status`, `detail`, `placeId?` | 官方；稳定 ID，不使用标题/日期拼接 |
| Place | `placeId`, `name`, `verifiedLocation`, `navigationTarget?`, `locationType` | 官方；坐标与定位语义需审核 |
| Stop | `stopId`, `activityId`, `placeId`, `order` | 官方；同一 Place 可多次到访 |
| Route Segment | `segmentId`, `fromStopId`, `toStopId`, `mode`, `geometry?`, `verifiedStatus` | 官方；路线与行程版本保持一致 |
| Official Task | `taskId`, `title`, `priority`, `dueDate?`, `activityId?/dayId?`, `status`, `archiveReason?` | 官方；显式归档 |
| Local Store | `notesByActivityId`, `localTasks`, `completionByTaskId`, `archivedSnapshots`, `schemaVersion` | iPhone 本机；备份和迁移 |

**技术实施弹性：** 以上是必须满足的概念数据关系，不强制要建立七张数据库表。可以按当前 PWA 的体量使用静态 JSON + 浏览器本地存储，只要满足稳定 ID、可迁移、可校验与数据分层。

**官方文件公开性：** Netlify 的静态数据通常可被知晓链接的人访问。官方数据可包含公共酒店名称、公开地址、行程时间；禁止包含私人确认号、真实票券二维码、可控制订单的链接或敏感联系资料。

## 5. 失败处理、迁移与一致性规则

| 情况 | 用户可见表现 | 数据处理 |
|---|---|---|
| 云端新版本成功 | 显示新数据版本、同步时间 | 原子性替换官方快照；本地数据不变 |
| 云端文件不完整 | 显示同步失败与继续使用旧版 | 拒绝提交，不归档消失的任务 |
| 某活动跨日、改时刻 | 时间线与地图更新 | Activity ID 不变；备注和关联任务保留 |
| 官方明确删除活动 | 当前行程不再显示 | 孤立备注保留至恢复区/备份 |
| 官方任务正式归档 | 从未完成消失，在归档可查看 | 保留本机完成状态及任务快照 |
| 地图路径生成失败 | 仅标明该段未核验 | 不显示虚假道路轨迹 |
| 地图底图离线 | 地点列表可查看，地图显示离线提示 | 本地文字行程、个人记录可用 |
| 原有 V1 本机数据迁移 | 在测试环境验证后再上线 | 先备份，再升级；失败可回退 |

## 10. 交付优先级、验证顺序与边界

**全部下列模块属于 P0 最终必备**，但可以分波交付并回归测试：

- **Wave 1：基础阅读与稳定同步。** 结构化行程、只读时间线、活动详情、双版本号、手动同步、离线文字快照、稳定 ID。
- **Wave 2：本地信息与待办。** 备注自动保存、官方 + 本地 To-do、归档、排序、导出导入、V1 数据迁移。
- **Wave 3：可信地图。** 地点核验、每日 Stop、预计算 GeoJSON 路段、筛选和显隐、Google Maps 单段/当前位置导航、缺失路段降级。

**P1：** 更精细的同步差异摘要、地图筛选便利性、体验优化。  
**P2：** 全程地图总览、站内搜索等有明确使用需要才做。

**“可用版本”判定：** 即使 Wave 1 可先上线验证，也不能因为仅有图钉或直线，就宣称满足“每日真实动线图”的 P0 验收。
